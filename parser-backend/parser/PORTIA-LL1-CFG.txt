PORTIA LL(1)-Compliant Context-Free Grammar
============================================

This document is a STRICT MIRROR of the Lark grammar (portia.lark).
Every production listed here corresponds directly to a rule in the implementation.
The grammar, documentation, and parser describe the SAME language.

Terminals: global, local, func, return, if, else, switch, case, default, for, while, do, break,
           trap, thread, threadln, using, weave, main, int, long, float, double, char, string,
           bool, void, var, const, true, false, id, intlit, longlit, floatlit, doublelit,
           charlit, stringlit, =, +=, -=, *=, /=, %=, ==, !=, <, >, <=, >=, &&, ||, !,
           +, -, *, /, %, ++, --, .., (, ), {, }, [, ], ;, ,, :, .

============================================
PROGRAM STRUCTURE
============================================
// STRICT SECTION ORDERING:
// 1. Global declarations (0 or more) - must start with GLOBAL keyword
// 2. Bare top-level arrays (0 or more) - type id[size] = {...};
// 3. Weave definitions (0 or more) - weave type definitions
// 4. Weave instances (0 or more) - instances of weave types
// 5. Function declarations (0 or more) - all func definitions
// 6. Main block (exactly one, required, must be last)
// BARE SCALAR DECLARATIONS FORBIDDEN at top level (e.g., "int x = 5;" is illegal)
// Bare arrays allowed: int arr[3] = {1,2,3}; (array bracket required after id)
// STRICT TYPE-LITERAL MATCHING: declarations accept only matching literal types
// Expressions are FORBIDDEN in all declaration contexts
// EMPTY INITIALIZERS FORBIDDEN: {} is syntactically impossible (R2 compliant)

<program> → <global_section>

// Global section: processes globals/weaves/arrays, then transitions to functions or main
// TYPE ID at top level requires [ (array) - scalar declarations forbidden
// INT MAIN is the main function entry point
<global_section> → <global_decl> <global_section>
<global_section> → int id <int_array_with_init> ; <global_section>
<global_section> → long id <long_array_with_init> ; <global_section>
<global_section> → float id <float_array_with_init> ; <global_section>
<global_section> → double id <double_array_with_init> ; <global_section>
<global_section> → char id <char_array_with_init> ; <global_section>
<global_section> → string id <string_array_with_init> ; <global_section>
<global_section> → bool id <bool_array_with_init> ; <global_section>
<global_section> → weave id { <field_list> } ; <global_section>
<global_section> → id <weave_inst_decl> <global_section>
<global_section> → <function_decl> <func_and_main>
<global_section> → int main ( ) { <main_body> }

// Function section: one or more functions, then mandatory main
// Once here, no more globals allowed - strict section ordering enforced
<func_and_main> → <function_decl> <func_and_main>
<func_and_main> → int main ( ) { <main_body> }

// Global declarations - MUST start with GLOBAL keyword
// Each type accepts ONLY its matching literal type
<global_decl> → global <mutability> int id = intlit <int_global_cont> ;
<global_decl> → global <mutability> long id = longlit <long_global_cont> ;
<global_decl> → global <mutability> float id = floatlit <float_global_cont> ;
<global_decl> → global <mutability> double id = doublelit <double_global_cont> ;
<global_decl> → global <mutability> char id = charlit <char_global_cont> ;
<global_decl> → global <mutability> string id = stringlit <string_global_cont> ;
<global_decl> → global <mutability> bool id = <bool_lit> <bool_global_cont> ;

// All function declarations (start with FUNC)
// R10 strict return type enforcement - each uses type-specific function body
<function_decl> → func int <func_ret_int>
<function_decl> → func long <func_ret_long>
<function_decl> → func float <func_ret_float>
<function_decl> → func double <func_ret_double>
<function_decl> → func char <func_ret_char>
<function_decl> → func string <func_ret_string>
<function_decl> → func bool <func_ret_bool>
<function_decl> → func id <func_ret_weave>
<function_decl> → func void id ( ) { <function_body_void> }

// Boolean literal helper (used where true/false is needed)
<bool_lit> → true
<bool_lit> → false

FUNCTIONS

// R10 — Strict Return Type Enforcement
// Return statements are syntactically restricted to the declared return type category
// Scalar returns: type-specific expressions (literals and casts filtered at top level)
// Array returns: identifier only (no literals, no expressions)
// Weave returns: identifier only (no field access)
// Void returns: bare return only

// Function return type tails - select appropriate body based on return type category
<func_ret_int> → id ( <param_list> ) { <function_body_int> }
<func_ret_int> → <array_dims> id ( <param_list> ) { <function_body_array> }

<func_ret_long> → id ( <param_list> ) { <function_body_long> }
<func_ret_long> → <array_dims> id ( <param_list> ) { <function_body_array> }

<func_ret_float> → id ( <param_list> ) { <function_body_float> }

<func_ret_double> → id ( <param_list> ) { <function_body_double> }

============================================
CONDITION EXPRESSIONS (STRICT BOOLEAN DISCIPLINE)
============================================
// Complete redesign for strict boolean enforcement:
// - ONLY boolean-producing constructs allowed at top level
// - Relational expressions ALWAYS require comparison operator
// - Arithmetic expressions FORBIDDEN without comparison
// - Type casts FORBIDDEN without comparison  
// - Numeric literals FORBIDDEN standalone
// - Parenthesized arithmetic MUST have comparison (inside OR outside)
//
// Allowed:
// - Boolean identifiers: if (x)
// - Boolean literals: if (true), if (false)
// - Relational expressions: if (x < 5), if (a == b), if (2 < 3)
// - Logical combinations: if (x && y), if (a || b)
// - Negation: if (!x), if (!(a < b))
// - Paren arithmetic with compare inside: if ((x + 5 > 10))
// - Paren arithmetic with compare outside: if ((x + 5) > 10)
//
// Disallowed (syntax error):
// - Standalone numeric literals: if (2), if (3.14)
// - Standalone arithmetic: if (x + 5), if (a * b)
// - Standalone type casts: if (int(5))
// - Paren arithmetic without comparison: if ((x + 5)), if ((3 + 2))
// - Mixed: if ((x < 5) || (3 + 2))
